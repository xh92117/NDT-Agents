# Inspection Plan Skill V1

## Purpose

S4-02 creates and validates provider-neutral inspection-plan candidates. It consumes exact-scope
S4-01 Technical QA evidence, the S3-07 published index, the S3-08 standard catalog, and the generated
`TPL-INSPECTION-PLAN-V1` template. It does not generate an approval, authorize formal use, operate an
instrument, or replace independent review.

## Template

The V1 template contains seventeen ordered sections: objective; scope; structure and component;
applicable basis; method and layout; equipment and calibration; procedure; sampling and coverage;
acceptance criteria; safety; data management; quality control; schedule; deliverables; limitations;
review and approval; and missing-input handling. The template is generated by
`tools/generate_fixture_catalog.py`; its file and catalog hashes are checked for drift.

## Typed content

`InspectionPlanRequest@1.0.0` binds the task, scenario, objective, structure and component IDs,
ontology classes, requested methods, region, applicability date, standard types, and template ID.
Missing request values are allowed only so the plan can preserve an explicit gap.

`InspectionPlanCandidate@1.0.0` carries ordered sections, registered-dimensional quantities,
planned methods, exact standard bases, input gaps, limitations, deliverables, and one immutable
Technical QA result. Methods bind equipment, calibration, procedure, sampling quantity, acceptance
bases, and safety controls. A gap binds field path, reason, impact, owner role, and blocking state.

`InspectionPlanResult@1.0.0` binds exact scope, Skill/template/request/QA hashes, validated content,
issues, plan hash, and result hash. It always sets `review_required=true`,
`approval_state=PENDING`, and `formal_use_allowed=false`.

## Validation

- Required sections must appear exactly once in template order; unknown sections fail.
- All requested and planned method codes must use the V1 ontology.
- Every numeric target uses a registered dimension/unit pair and ordered non-negative bounds.
- Every method reference resolves to a declared quantity and standard basis.
- Missing required request inputs must appear as explicit gaps; a blocking gap returns
  `NEEDS_USER`.
- The QA result hash and exact scope are rechecked and its status must be usable.
- Each basis resolves to an applicable QA claim and exact citation, then reconstructs the published
  index record and matching standard-version binding.
- S3-08 applicability rechecks scope, date, region, type, lifecycle, rights, roles, and supersession.

Critical scope, ontology, evidence, or applicability faults require a qualified human. Structural
completeness and missing-reference faults return a typed user-input stop. The boundary is
deterministic and makes no model, network, approval, publication, instrument, or retry call.

## Local evidence boundary

Synthetic tests cover the complete template, stable plan hashes, explicit and undeclared gaps,
unknown/missing methods, quantity and basis references, unit and range validation, standard region
applicability, cross-scope evidence, and approval-field injection. Expert completeness scoring and
TG-04 remain blocked by R-008 and R-009.
