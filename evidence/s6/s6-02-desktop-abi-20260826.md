# S6-02 Desktop ABI Evidence

## Result

The transport-independent Rust and Python desktop ABI is implemented on branch
`codex/s6-02-desktop-abi`. S6-02 remains `IN_PROGRESS`; the desktop window capability still grants
status only, and this evidence does not authorize invoke, cancel, signing, packaging, or release.

## Implemented boundary

- Rust and Python consume the same strict camelCase invoke, cancel, and error JSON fixtures.
- Both implementations compute the same canonical UTF-8 SHA-256 for invoke and cancel requests.
- Registry and target identities require exact lowercase SHA-256 values, and unknown fields fail
  closed.
- Cancellation is a distinct hash-bound intent. The application service verifies session, task, run,
  and registry authority, writes a scoped hash-only denial audit, and returns
  `DESKTOP_CANCEL_UNAVAILABLE` while no qualified adapter exists.
- Cancellation reasons use one 512-byte UTF-8 limit in both languages. A shared multibyte fixture
  proves that character count cannot bypass the byte budget.
- The Rust commands remain zero-action and include the validated request hash in post-validation
  errors. The application window has no invoke or cancel permission.

## Test-first record

The first Python run failed at import because the shared cancel and error models did not exist. The
first Rust run failed because the matching shared models and canonical hash path did not exist. After
implementation, the initial placeholder hashes differed from the actual canonical JSON; the tests
were updated to the independently observed canonical values and now require exact equality in both
languages. Convergence review then found `CCR-d658ba2-001`: Python bounded cancellation reasons by
characters while Rust bounded UTF-8 bytes. The approved repair added a shared multibyte fixture that
failed on Python before the change and is now rejected by both implementations.

## Remaining boundary

The ABI is not yet connected across a fixed native service process. The capability grants status
only. Native session installation, invoke and cancel grants, reconciliation after interruption,
signed installer identity, upgrade, rollback, live desktop E2E, immutable CI, TG-06, and release
evidence remain required. No production credential, network provider, real instrument, physical
action, approval, publication, or commercial release occurred.
