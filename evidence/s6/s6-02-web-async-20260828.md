## Implemented boundary

- SQLite persistence format version 2 adds one execution record per task. Version 1 databases
  migrate atomically at startup, and partial or unsupported schemas fail closed.
- New task, accepted event, exact-scope idempotency binding, and pending execution record commit in
  one transaction. The authenticated POST route returns the accepted snapshot before execution
  finishes.
- One versioned local coordinator claims accepted work with an exact owner and bounded lease,
  enforces a bounded active-task set, and prevents duplicate idempotent scheduling.
- A terminal event and execution completion commit atomically. Shutdown cancellation preserves the
  last committed state and claim instead of fabricating a terminal result.
- An expired claim may be reclaimed only while the task remains accepted. An expired claim that
  already entered running, review-required, or human-required state becomes blocked with
  `CLIENT_EXECUTION_RECOVERY_REQUIRED` and makes zero executor or provider calls.
- Recovery batch size, recovery sweeps, active tasks, stream wait, total stream duration, and stream
  batch count are bounded by `WorkbenchAsyncPolicy@1.0.0`.
- SSE preflights exact scope and cursor, then waits on post-commit event notifications. It performs
  no periodic repository polling and closes on terminal state or a configured bound.
- The browser incrementally decodes split UTF-8 response chunks, renders complete event blocks
  before close, rejects gaps, duplicates, malformed data, and cursor mismatches, and exposes one
  explicit resume action from the last acknowledged sequence.
